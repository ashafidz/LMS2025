RANCANGAN DATABASE UNTUK FITUR KEAMANAN KUIS ONLINE
Platform E-Learning EduGames
================================================================================

DOKUMEN REFERENSI:
- Proposal: Implementasi Fitur Keamanan Ujian Online Menggunakan Algoritma 
  Fisher-Yates Shuffle dan MediaPipe Face Mesh
- Activity Diagram: Mengerjakan Kuis, Mengelola Kuis, Melihat Hasil Kuis,
  Mengatur Opsi Keamanan, Melihat Laporan Integritas

================================================================================
OVERVIEW FITUR YANG DIKEMBANGKAN
================================================================================

Berdasarkan proposal dan activity diagram, fitur keamanan kuis mencakup:

1. DETEKSI PERPINDAHAN TAB (Tab Switching Detection)
   - Mencatat setiap kali student berpindah tab/aplikasi
   - Menghitung total pelanggaran perpindahan tab

2. PENGACAKAN SOAL (Fisher-Yates Shuffle)
   - Setiap student mendapat urutan soal yang berbeda
   - Implementasi algoritma Fisher-Yates untuk randomisasi

3. DETEKSI KAMERA (Face Detection - MediaPipe Face Mesh)
   - Deteksi wajah student selama mengerjakan kuis
   - Deteksi perilaku mencurigakan:
     * Menoleh kanan/kiri
     * Menunduk (melihat ke bawah)
     * Mendongak (melihat ke atas)
     * Wajah tidak terdeteksi
   - Pengambilan screenshot/foto saat terjadi pelanggaran

4. OPSI KEAMANAN KUIS (Security Options)
   - Instructor dapat mengaktifkan/menonaktifkan fitur keamanan
   - 3 opsi toggle: Deteksi Kamera, Deteksi Tab, Pengacakan Soal

5. LAPORAN INTEGRITAS (Integrity Report)
   - Per Student (per quiz attempt)
   - Per Quiz (aggregasi semua attempts)
   - Per Course (aggregasi semua quiz dalam kursus)

TABEL BARU YANG PERLU DIBUAT
================================================================================

1. TABEL: quiz_security_settings
   DESKRIPSI: Menyimpan pengaturan keamanan untuk setiap kuis
   RELASI: Setiap quiz memiliki 1 security setting (One-to-One)
   
   KOLOM:
   - id (bigint, PK, auto_increment)
   - quiz_id (bigint, FK to quizzes, UNIQUE)
   - enable_camera_detection (boolean, default: false)
   - enable_tab_detection (boolean, default: false)
   - enable_question_shuffle (boolean, default: false)
   - camera_violation_threshold (integer, default: 3)
     * Batas toleransi pelanggaran kamera sebelum dianggap mencurigakan
   - tab_violation_threshold (integer, default: 5)
     * Batas toleransi perpindahan tab
   - face_detection_interval_seconds (integer, default: 5)
     * Interval deteksi wajah dalam detik
   - created_at (timestamp)
   - updated_at (timestamp)
   
   INDEXES:
   - PRIMARY KEY (id)
   - UNIQUE KEY (quiz_id)
   - FOREIGN KEY (quiz_id) REFERENCES quizzes(id) ON DELETE CASCADE


2. TABEL: quiz_attempt_question_order
   DESKRIPSI: Menyimpan urutan soal yang sudah diacak untuk setiap attempt
   RELASI: Many-to-One dengan quiz_attempts, Many-to-One dengan questions
   TUJUAN: Implementasi Fisher-Yates Shuffle - setiap student punya urutan berbeda
   
   KOLOM:
   - id (bigint, PK, auto_increment)
   - attempt_id (bigint, FK to quiz_attempts)
   - question_id (bigint, FK to questions)
   - shuffled_order (integer, NOT NULL)
     * Urutan soal setelah diacak (1, 2, 3, dst)
   - created_at (timestamp)
   
   INDEXES:
   - PRIMARY KEY (id)
   - UNIQUE KEY (attempt_id, question_id)
     * Memastikan tidak ada duplikasi soal dalam satu attempt
   - INDEX (attempt_id, shuffled_order)
     * Untuk query soal berdasarkan urutan
   - FOREIGN KEY (attempt_id) REFERENCES quiz_attempts(id) ON DELETE CASCADE
   - FOREIGN KEY (question_id) REFERENCES questions(id) ON DELETE CASCADE


3. TABEL: monitoring_logs
   DESKRIPSI: Log aktivitas monitoring selama student mengerjakan kuis
   RELASI: Many-to-One dengan quiz_attempts
   TUJUAN: Mencatat semua pelanggaran (tab switch & camera flags)
   
   KOLOM:
   - id (bigint, PK, auto_increment)
   - attempt_id (bigint, FK to quiz_attempts)
   - violation_type (enum: 'tab_switch', 'face_not_detected', 'look_left', 
                     'look_right', 'look_down', 'look_up')
   - violation_timestamp (timestamp, NOT NULL)
     * Waktu terjadinya pelanggaran
   - duration_seconds (integer, nullable)
     * Durasi pelanggaran (untuk face detection)
   - screenshot_path (string, nullable)
     * Path foto/screenshot saat pelanggaran terjadi
   - additional_data (json, nullable)
     * Data tambahan seperti koordinat wajah, confidence score, dll
   - created_at (timestamp)
   
   INDEXES:
   - PRIMARY KEY (id)
   - INDEX (attempt_id, violation_type)
     * Untuk query pelanggaran berdasarkan tipe
   - INDEX (attempt_id, violation_timestamp)
     * Untuk timeline pelanggaran
   - FOREIGN KEY (attempt_id) REFERENCES quiz_attempts(id) ON DELETE CASCADE


4. TABEL: quiz_attempt_integrity_summary
   DESKRIPSI: Ringkasan integritas untuk setiap quiz attempt
   RELASI: One-to-One dengan quiz_attempts
   TUJUAN: Mempercepat laporan integritas tanpa hitung ulang dari monitoring_logs
   
   KOLOM:
   - id (bigint, PK, auto_increment)
   - attempt_id (bigint, FK to quiz_attempts, UNIQUE)
   - total_tab_switches (integer, default: 0)
   - total_face_violations (integer, default: 0)
     * Total semua pelanggaran face detection
   - face_not_detected_count (integer, default: 0)
   - look_left_count (integer, default: 0)
   - look_right_count (integer, default: 0)
   - look_down_count (integer, default: 0)
   - look_up_count (integer, default: 0)
   - integrity_score (decimal(5,2), nullable)
     * Skor integritas 0-100 (100 = tidak ada pelanggaran)
   - risk_level (enum: 'low', 'medium', 'high', nullable)
     * Level risiko berdasarkan total pelanggaran
   - flagged_for_review (boolean, default: false)
     * Flag untuk instructor review jika melewati threshold
   - created_at (timestamp)
   - updated_at (timestamp)
   
   INDEXES:
   - PRIMARY KEY (id)
   - UNIQUE KEY (attempt_id)
   - INDEX (integrity_score)
   - INDEX (risk_level)
   - INDEX (flagged_for_review)
   - FOREIGN KEY (attempt_id) REFERENCES quiz_attempts(id) ON DELETE CASCADE


5. TABEL: camera_access_logs
   DESKRIPSI: Log permintaan akses kamera dan status persetujuan
   RELASI: Many-to-One dengan quiz_attempts
   TUJUAN: Audit trail untuk akses kamera student
   
   KOLOM:
   - id (bigint, PK, auto_increment)
   - attempt_id (bigint, FK to quiz_attempts)
   - permission_requested_at (timestamp, NOT NULL)
   - permission_granted (boolean, nullable)
     * null = belum dijawab, true = granted, false = denied
   - permission_granted_at (timestamp, nullable)
   - browser_info (text, nullable)
     * User agent dan browser info
   - error_message (text, nullable)
     * Pesan error jika akses kamera gagal
   - created_at (timestamp)
   
   INDEXES:
   - PRIMARY KEY (id)
   - INDEX (attempt_id)
   - FOREIGN KEY (attempt_id) REFERENCES quiz_attempts(id) ON DELETE CASCADE

================================================================================
ALUR DATA BERDASARKAN ACTIVITY DIAGRAM
================================================================================

FLOW 1: INSTRUCTOR MENGATUR OPSI KEAMANAN KUIS
----------------------------------------------
1. Instructor membuka form "Add/Edit Quiz"
2. Instructor toggle opsi keamanan (3 checkbox):
   - Enable Camera Detection
   - Enable Tab Detection  
   - Enable Question Shuffle
3. System validasi input
4. System simpan ke tabel: quiz_security_settings
5. Jika update: UPDATE quiz_security_settings WHERE quiz_id = ?
6. Jika insert: INSERT INTO quiz_security_settings


FLOW 2: STUDENT MENGERJAKAN KUIS (dengan keamanan aktif)
---------------------------------------------------------
1. Student klik "Mulai Kuis"
2. System cek quiz_security_settings untuk quiz tersebut
3. Jika enable_camera_detection = true:
   - System request camera permission
   - INSERT INTO camera_access_logs
   - Jika ditolak: tampilkan error, stop quiz
4. System membuat quiz_attempt baru
   - INSERT INTO quiz_attempts (status = 'in_progress')
5. Jika enable_question_shuffle = true:
   - System jalankan Fisher-Yates Shuffle
   - System simpan urutan acak ke quiz_attempt_question_order
   - INSERT INTO quiz_attempt_question_order untuk setiap soal
6. System tampilkan soal berdasarkan shuffled_order

[ITERASI MENGERJAKAN SOAL]
7. Student membaca soal & menjawab
8. Monitoring berjalan parallel:
   
   A. Tab Detection (jika enable_tab_detection = true):
      - JavaScript detect "visibilitychange" event
      - Saat tab switch terdeteksi:
        * INSERT INTO monitoring_logs 
          (violation_type = 'tab_switch', violation_timestamp = NOW())
   
   B. Camera Detection (jika enable_camera_detection = true):
      - MediaPipe Face Mesh running setiap X detik (face_detection_interval_seconds)
      - Jika face not detected:
        * INSERT INTO monitoring_logs (violation_type = 'face_not_detected')
      - Jika look_left/right/up/down terdeteksi > threshold duration:
        * Ambil screenshot (canvas.toDataURL)
        * Simpan file ke storage
        * INSERT INTO monitoring_logs 
          (violation_type = 'look_left', screenshot_path = '...')
   
   C. Indikasi Kecurangan Real-time:
      - System cek total pelanggaran dari monitoring_logs WHERE attempt_id = ?
      - Jika total > threshold: tampilkan warning di UI

9. Student submit jawaban: INSERT/UPDATE student_answers
10. Ulangi step 7-9 untuk semua soal

[SELESAI KUIS]
11. Student klik "Selesaikan Kuis" atau timeout
12. System hitung skor akhir
13. System hitung integrity summary:
    - COUNT pelanggaran per type dari monitoring_logs
    - Hitung integrity_score (rumus: 100 - (total_violations * penalty))
    - Tentukan risk_level berdasarkan total violations
    - Cek apakah flagged_for_review 
      (jika violations > camera_violation_threshold atau tab_violation_threshold)
14. System simpan:
    - UPDATE quiz_attempts (score = ?, status = ?, end_time = NOW())
    - INSERT INTO quiz_attempt_integrity_summary
15. System tampilkan halaman hasil (skor & status kelulusan)


FLOW 3: STUDENT MELIHAT HASIL KUIS (tanpa detail pelanggaran)
--------------------------------------------------------------
1. Student buka menu "Kuis" di sidebar
2. Student klik "Lihat" pada salah satu quiz attempt
3. System query:
   - SELECT * FROM quiz_attempts WHERE id = ? AND student_id = ?
4. System tampilkan:
   - Preview kuis (info soal, durasi, riwayat)
   - Tabel status kelulusan per attempt
5. Student klik "Lihat" pada attempt yang selesai
6. System redirect ke halaman detail attempt
7. System ambil data:
   - student_answers JOIN questions (untuk review jawaban)
   - quiz_attempt_integrity_summary (hanya integrity_score & risk_level)
8. System tampilkan:
   - Halaman review jawaban (Student view)
   - Badge/label integrity_score (misal: "Integrity: 95/100")
   - TIDAK menampilkan detail pelanggaran (privasi student)


FLOW 4: INSTRUCTOR MELIHAT LAPORAN INTEGRITAS PER PERCOBAAN
------------------------------------------------------------
1. Instructor buka menu "Lihat Nilai" di dashboard lesson
2. Instructor klik tombol "Lihat Riwayat" pada salah satu siswa
3. System query attempts untuk siswa tersebut
4. Instructor klik "Check Laporan" pada salah satu attempt
5. System query data integritas attempt tersebut:
   - SELECT * FROM quiz_attempt_integrity_summary WHERE attempt_id = ?
   - SELECT * FROM monitoring_logs WHERE attempt_id = ? ORDER BY violation_timestamp
6. System validasi: Apakah data tersedia?
   - Jika tidak ada: Tampilkan "Belum ada partisipan"
7. System tampilkan Halaman Detail Laporan Integritas:
   - Bukti foto/screenshot dari monitoring_logs (screenshot_path)
   - Log waktu pelanggaran (violation_timestamp)
   - Total pelanggaran per tipe
   - Integrity score & risk level
   - Tombol "Revisi Skor" (jika flagged_for_review)


FLOW 5: INSTRUCTOR MELIHAT REKAPITULASI LAPORAN PER KUIS
---------------------------------------------------------
1. Instructor buka halaman "Daftar Pelajaran/Kuis"
2. Instructor klik tombol "Rekapitulasi Laporan Integritas" pada kuis tertentu
3. System query semua attempts untuk kuis tersebut:
   - SELECT quiz_attempts.*, quiz_attempt_integrity_summary.*
     FROM quiz_attempts
     JOIN quiz_attempt_integrity_summary ON quiz_attempts.id = quiz_attempt_integrity_summary.attempt_id
     WHERE quiz_attempts.quiz_id = ?
4. System query aggregasi monitoring_logs:
   - SELECT attempt_id, violation_type, COUNT(*) as total
     FROM monitoring_logs
     WHERE attempt_id IN (...)
     GROUP BY attempt_id, violation_type
5. System validasi: Apakah ada data?
   - Jika tidak: Tampilkan "Belum ada partisipan"
6. System hitung statistik & tampilkan Dashboard Rekapitulasi:
   - Jumlah total attempts
   - Rata-rata integrity score
   - Distribusi risk level (low/medium/high)
   - Jumlah attempts yang di-flag untuk review
   - Chart/grafik pelanggaran (tab switch vs camera violations)
   - Tabel detail per siswa (nama, score, integrity_score, risk_level)


FLOW 6: INSTRUCTOR MELIHAT REKAPITULASI LAPORAN PER KURSUS
-----------------------------------------------------------
1. Instructor buka halaman "Manajemen Kursus"
2. Instructor klik tombol "Rekapitulasi Laporan Integritas" pada kursus tertentu
3. System query semua kuis dalam kursus:
   - SELECT quizzes.* FROM quizzes
     JOIN lessons ON quizzes.id = lessons.lessonable_id
     JOIN modules ON lessons.module_id = modules.id
     WHERE modules.course_id = ? AND lessons.lessonable_type = 'App\Models\Quiz'
4. System query semua attempts & integrity data untuk semua kuis tersebut
5. System query & akumulasi data monitoring_logs untuk seluruh kuis
6. System validasi: Apakah ada aktivitas kuis?
   - Jika tidak: Tampilkan "Belum ada aktivitas kuis"
7. System tampilkan Dashboard Rekapitulasi Kursus:
   - Profil risiko integritas siswa (agregasi dari semua kuis)
   - Chart trend pelanggaran sepanjang kursus
   - Tabel siswa dengan high risk (perlu perhatian khusus)
   - Export laporan (PDF/Excel)


FLOW 7: INSTRUCTOR MELAKUKAN REVISI SKOR
-----------------------------------------
1. Instructor berada di halaman Laporan Integritas (per attempt)
2. Instructor klik tombol "Revisi Skor"
3. System tampilkan Form Modal Revisi Skor
4. Instructor input nilai baru (0-100)
5. Instructor input alasan revisi (textarea)
6. Instructor klik "Simpan Perubahan"
7. System validasi input (nilai harus angka 0-100)
8. System update:
   - UPDATE quiz_attempts SET score = ? WHERE id = ?
   - INSERT INTO score_revision_logs (optional table untuk audit)
9. System tampilkan pesan sukses & skor terbaru

QUERY PENTING UNTUK LAPORAN INTEGRITAS
================================================================================

QUERY 1: Get Integrity Summary per Attempt
-------------------------------------------
SELECT 
    qa.id AS attempt_id,
    qa.quiz_id,
    qa.student_id,
    u.name AS student_name,
    qa.score AS quiz_score,
    qa.status,
    qais.integrity_score,
    qais.risk_level,
    qais.total_tab_switches,
    qais.total_face_violations,
    qais.flagged_for_review,
    qa.start_time,
    qa.end_time
FROM quiz_attempts qa
JOIN users u ON qa.student_id = u.id
LEFT JOIN quiz_attempt_integrity_summary qais ON qa.id = qais.attempt_id
WHERE qa.id = ?;


QUERY 2: Get All Violations for an Attempt
-------------------------------------------
SELECT 
    id,
    violation_type,
    violation_timestamp,
    duration_seconds,
    screenshot_path,
    additional_data
FROM monitoring_logs
WHERE attempt_id = ?
ORDER BY violation_timestamp ASC;


QUERY 3: Count Violations by Type for an Attempt
-------------------------------------------------
SELECT 
    violation_type,
    COUNT(*) AS violation_count
FROM monitoring_logs
WHERE attempt_id = ?
GROUP BY violation_type;


QUERY 4: Get Integrity Report for All Attempts of a Quiz
---------------------------------------------------------
SELECT 
    qa.id AS attempt_id,
    u.name AS student_name,
    u.email AS student_email,
    qa.score AS quiz_score,
    qa.status,
    qais.integrity_score,
    qais.risk_level,
    qais.total_tab_switches,
    qais.total_face_violations,
    qais.flagged_for_review
FROM quiz_attempts qa
JOIN users u ON qa.student_id = u.id
LEFT JOIN quiz_attempt_integrity_summary qais ON qa.id = qais.attempt_id
WHERE qa.quiz_id = ?
ORDER BY qais.integrity_score ASC, qa.created_at DESC;


QUERY 5: Get Aggregate Statistics for a Quiz
---------------------------------------------
SELECT 
    COUNT(qa.id) AS total_attempts,
    COUNT(DISTINCT qa.student_id) AS total_students,
    AVG(qais.integrity_score) AS avg_integrity_score,
    AVG(qa.score) AS avg_quiz_score,
    SUM(CASE WHEN qais.risk_level = 'high' THEN 1 ELSE 0 END) AS high_risk_count,
    SUM(CASE WHEN qais.risk_level = 'medium' THEN 1 ELSE 0 END) AS medium_risk_count,
    SUM(CASE WHEN qais.risk_level = 'low' THEN 1 ELSE 0 END) AS low_risk_count,
    SUM(CASE WHEN qais.flagged_for_review = 1 THEN 1 ELSE 0 END) AS flagged_count
FROM quiz_attempts qa
LEFT JOIN quiz_attempt_integrity_summary qais ON qa.id = qais.attempt_id
WHERE qa.quiz_id = ?;


QUERY 6: Get Course-Level Integrity Report
-------------------------------------------
SELECT 
    c.id AS course_id,
    c.title AS course_title,
    q.id AS quiz_id,
    q.title AS quiz_title,
    COUNT(qa.id) AS total_attempts,
    AVG(qais.integrity_score) AS avg_integrity_score,
    SUM(CASE WHEN qais.flagged_for_review = 1 THEN 1 ELSE 0 END) AS flagged_count
FROM courses c
JOIN modules m ON c.id = m.course_id
JOIN lessons l ON m.id = l.module_id
JOIN quizzes q ON l.lessonable_id = q.id AND l.lessonable_type = 'App\\Models\\Quiz'
LEFT JOIN quiz_attempts qa ON q.id = qa.quiz_id
LEFT JOIN quiz_attempt_integrity_summary qais ON qa.id = qais.attempt_id
WHERE c.id = ?
GROUP BY c.id, q.id
ORDER BY avg_integrity_score ASC;


QUERY 7: Get Student Risk Profile (across all quizzes in a course)
-------------------------------------------------------------------
SELECT 
    u.id AS student_id,
    u.name AS student_name,
    COUNT(qa.id) AS total_attempts,
    AVG(qais.integrity_score) AS avg_integrity_score,
    SUM(qais.total_tab_switches) AS total_tab_switches,
    SUM(qais.total_face_violations) AS total_face_violations,
    MAX(CASE WHEN qais.risk_level = 'high' THEN 1 ELSE 0 END) AS has_high_risk
FROM users u
JOIN quiz_attempts qa ON u.id = qa.student_id
JOIN quizzes q ON qa.quiz_id = q.id
JOIN lessons l ON q.id = l.lessonable_id AND l.lessonable_type = 'App\\Models\\Quiz'
JOIN modules m ON l.module_id = m.id
LEFT JOIN quiz_attempt_integrity_summary qais ON qa.id = qais.attempt_id
WHERE m.course_id = ?
GROUP BY u.id
ORDER BY avg_integrity_score ASC;

================================================================================
CATATAN IMPLEMENTASI
================================================================================

1. FISHER-YATES SHUFFLE IMPLEMENTATION
   - Algoritma shuffle dilakukan di backend (PHP/Laravel)
   - Setiap kali quiz_attempt dibuat, shuffle urutan soal
   - Simpan hasil shuffle di quiz_attempt_question_order
   - Frontend fetch soal berdasarkan shuffled_order

2. MEDIAPIPE FACE MESH INTEGRATION
   - Library: TensorFlow.js + MediaPipe Face Mesh
   - Running di browser (client-side)
   - Interval checking sesuai face_detection_interval_seconds
   - Kirim violation ke backend via AJAX/Fetch API secara real-time

3. TAB SWITCHING DETECTION
   - Menggunakan JavaScript Page Visibility API
   - Event: document.addEventListener('visibilitychange')
   - Kirim log ke backend saat tab hidden

4. SCREENSHOT/PHOTO CAPTURE
   - Gunakan HTML5 Canvas API
   - Ambil frame dari video stream
   - Convert to base64 atau blob
   - Upload ke storage (storage/app/monitoring_screenshots/)
   - Simpan path di monitoring_logs.screenshot_path

5. INTEGRITY SCORE CALCULATION
   - Formula: 100 - (total_violations × penalty_per_violation)
   - Penalty dapat dikonfigurasi per violation type
   - Risk Level:
     * low: integrity_score >= 80
     * medium: 50 <= integrity_score < 80
     * high: integrity_score < 50

6. REAL-TIME MONITORING
   - Backend API endpoint: POST /api/quiz-attempts/{id}/log-violation
   - Request body: {violation_type, timestamp, screenshot, additional_data}
   - Response: {success, total_violations, warning_message}

7. DATABASE PERFORMANCE
   - Index semua foreign keys
   - Index pada attempt_id, violation_type, violation_timestamp
   - Consider partitioning monitoring_logs jika data sangat besar
   - Archive old monitoring data setelah periode tertentu

8. STORAGE MANAGEMENT
   - Screenshot disimpan dengan naming: {attempt_id}_{timestamp}_{violation_type}.jpg
   - Cleanup job: Hapus screenshot lama (> 90 hari) untuk hemat storage
   - Pertimbangkan cloud storage (S3) untuk production
